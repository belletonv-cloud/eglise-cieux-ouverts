Contexte bref
- Repo local : eglise-cieux-ouverts
- Fichier ciblé : components/blocks/BlockAspirations.vue
- Problème : lors du rendu SSR / hydratation, le composant émet des styles inline numériques (opacity, transform translateY(px), top en px) depuis le JS. Ces inline styles provoquent un flash visuel à l’hydratation. L’animation côté client doit rester pilotée par CSS via variables (--aspir-*) et classes (.is-active, .js-mounted). Mobile doit rester statique (sans animation).

But recherché (une phrase)
- Empêcher toute émission de styles inline numériques pendant SSR/hydratation et conserver l’animation CSS-driven côté client.

Plan de travail détaillé — étapes à suivre (ordre impératif)

1) Préparation / audit rapide
  1.1 Ouvrir components/blocks/BlockAspirations.vue.
  1.2 Repérer les bindings : template contient :style="getTitleStyle()", :style="getLineStyle(i)", :style="getTextStyle(i)", :style="getCircleStyle(i)". Noter chaque fonction à modifier.
  1.3 Vérifier l’existence de refs/flags : mounted, isMobile, sectionRef, class .js-mounted déjà injectée sur le <section>.

2) Objectif précis par fonction (changer seulement ce fichier)
  2.1 getTitleStyle()
    - But : ne jamais renvoyer une propriété d’affichage numérique (ex. { opacity: 0 }) côté serveur.
    - Implémentation demandée :
      - Côté SSR (typeof window === 'undefined' OR !mounted.value) retourner {}.
      - Au montage client, activer l’apparition via CSS en s’appuyant sur la classe .js-mounted. Conserver le flag mounted (déjà présent). Ne pas ajouter un nouveau binding dans le template — garder :style="getTitleStyle()" si nécessaire mais veiller à ce que la fonction retourne {} côté SSR.
      - Ajouter (dans la même SFC <style>) une règle CSS minimale, p.ex :
        .block-aspirations .aspirations-title { opacity: 0; transition: opacity 320ms ease-out; }
        .block-aspirations.js-mounted .aspirations-title { opacity: 1; }
      - Résultat : côté serveur le titre n’a pas d’inline opacity, côté client la .js-mounted permet l’animation d’opacité.

  2.2 getLineStyle()
    - But : ne pas renvoyer transform/opacity numériques pendant SSR.
    - Implémentation demandée :
      - Si typeof window === 'undefined' OR !mounted.value => return {}.
      - Pour mobile (isMobile.value), ne renvoyer que styles inoffensifs ou variables CSS si absolument nécessaires; idéalement laisser la CSS gérer le rendu mobile et retourner {} aussi.
      - En pratique, simplifier la fonction pour qu’elle n’expédie plus transform/opacity inline du tout et laisse les transitions au CSS (.aspiration-line.is-active .aspiration-text).

  2.3 getTextStyle(index)
    - But : côté SSR / avant montage, ne jamais retourner translateY(px) ni opacity numérique inline.
    - Implémentation demandée :
      - Early return : if (typeof window === 'undefined' || !mounted.value) return {}.
      - Côté client, ne renvoyer que des CSS variables (ex. { '--aspir-text-delay': '0.12s', '--aspir-text-duration': '0.28s', '--aspir-text-timing': 'ease' }) — jamais transform/opacity en pixels ou nombre.
      - Laisser la CSS existante .aspiration-line.is-active .aspiration-text piloter transform/opacity finals.

  2.4 getCircleStyle(index)
    - But : même règle, pas de translateY(px)/top/opacity numériques en SSR.
    - Implémentation demandée :
      - Early return : if (typeof window === 'undefined' || !mounted.value) return { left: (index*30 + circleLeftOffset) + 'px' } OR simplement return { left: ... } si left doit exister pour le layout SSR (left en px est acceptable).
      - Côté client, renvoyer uniquement CSS variables : '--aspir-start-y', '--aspir-delay', '--aspir-duration', '--aspir-opacity-duration', '--aspir-timing', '--aspir-opacity-timing', left. Ne pas renvoyer transform: translateY(...) inline ni opacity numeric inline.

3) Vérifications logiques complémentaires
  3.1 isMobile et activeCount
    - isMobile.value est initialisé dans onMounted (bien). S’assurer que aucune computed() qui s’exécute au SSR n’utilise isMobile.value. Si activeCount est utilisé pendant SSR, garantir qu’il ne s’appuie pas sur isMobile.value avant le montage (par exemple, dans activeCount computed faire : if (typeof window === 'undefined' || !mounted.value) return 0 OR return safe default).
    - L’idée : pendant SSR, rien n’est considéré actif (activeCount = 0), puis au montage client la logique usuelle s’exécute.

  3.2 getTimingFor(index)
    - Laisser la logique d’import/fetch intacte. getTimingFor peut rester sync et lire window.__aspirationsTimings s’il est déjà résolu. Aucune modification nécessaire sauf si elle fait des appels à window pendant SSR — protéger avec typeof window !== 'undefined'.

4) CSS minimal à ajouter/réorganiser (toujours dans ce SFC)
  - Ajouter ou confirmer ces règles (suffisantes et simples):

    .block-aspirations.js-mounted .aspirations-title { opacity: 1; }
    .block-aspirations:not(.js-mounted) .aspiration-circle,
    .block-aspirations:not(.js-mounted) .aspiration-line .aspiration-text {
      /* cacher les éléments animés côté SSR sur desktop pour éviter flash */
